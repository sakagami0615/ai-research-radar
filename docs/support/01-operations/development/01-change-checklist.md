# 01 再実行・状態遷移の変更時チェックリスト

上流ステージの再実行で下流を無効にするようなCLI変更では、上流を呼ぶSkillのすべての経路を合わせて確認する。実行時の現行契約は [CLI](../../../spec/03-detailed-design/cli/commands.md) と [実行記録](../../../spec/03-detailed-design/data-models/run-metadata.md)、品質改善の目標は [変更設計](../../../spec/05-decisions/audit-remediation/execution-and-reporting.md) を参照し、現行に適用済みと混同しない。

## 変更前に洗い出す経路

- 初回実行。
- レポート生成前の状態確認による補完実行。
- レビュー指摘後の修正ループ。
- エラー時の自己修正。

各経路について、上流実行前の下流の状態、上流の成功・失敗、下流を再実行するか・しないか、次に進む手順を明記する。日次経路は [通常手順](../../../../skills/agent-daily-run/SKILL.md) と [失敗・やり直し](../../../../skills/agent-daily-run/recovery.md) を両方確認する。

## 完了前の確認

- 初回はまだ下流を実行していない場合がある。未作成の入力で下流を前倒し実行しない。
- 上流が失敗した場合に下流の記録が残ることと、その記録の有効性を区別する。
- 上流の成功後に必要な下流の再実行が抜けていない。
- 正しい成果物を空の入力や途中結果で上書きしない。
- 変更したCLIと、各再実行経路のSkill・対応する設計・検証が整合している。

一つの経路だけ修正して完了とせず、洗い出した経路ごとに確認結果・未確認理由を記録する。実機確認とレビューは [テスト実行ガイド](../testing/README.md) と [レビュー運用](../review-and-improvement.md) に従う。
