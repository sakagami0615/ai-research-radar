# 05 設計判断・変更設計

1. [初期MVPの設計判断](initial-mvp-policy.md)：初期の方式と理由。二つの現行経路は基本設計を参照する。
2. [初期MVPの成功条件](initial-success-criteria.md)：現在の要件と区別して保存する初期の出典資料。
3. [監査に基づく品質改善](audit-remediation/README.md)：変更理由、目標仕様、受入・承認履歴。
4. [ドキュメント構成の判断](documentation-structure.md)：今回の分割と正本の規則。

採用した変更を現行に反映するときは、specの要求・要件／基本設計／詳細設計／検証と、supportの運用／適用状況を更新する。変更設計だけを更新して、現行仕様を読み替えさせない。次は [開発・運用支援](../../support/README.md)。
