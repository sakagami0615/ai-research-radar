# 運用・互換・追跡の受入

対象: N-02〜N-06。具体的条件は [非機能要件](../../01-requirements/02-definition/non-functional/README.md)を参照。

1. 手動とcron相当の環境でPATH・ディレクトリ・ログ・同日排他を確認する。テストモード(`entry-prompt-test.txt`)で実行し、`test_output/reports/daily/<date>.md` が生成され、実行前後で本番の `data/` / `reports/` の全ファイルのハッシュが変わらないことを確認する。
2. 選抜再実行後の企画状態を確認する。品質改善接続後は上流再実行・途中失敗・保存失敗で下流と承認が適切に失効し、旧試行が追えることを確認する。
3. UTC実測取得ログと評価日時を照合する。品質改善接続後はコード版・設定・試行・hashを対応させる。
4. 旧v1データを読み、品質評価を推測で追加しないことと、未知版の拒否を確認する。
5. Claude CodeとCodexそれぞれで同じ資料とSkillを読み、入力作成と確認ができることを記録する。
6. 機密値を含む設定やネスト値を含む検査用入力で、保存される記録へ機密値が残らないことを確認する。実際の機密値は使わない。

未確認のAgent・運用環境は未検証とする。
