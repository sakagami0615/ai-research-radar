# 01 要求整理・要件定義

要求整理、要件定義、未決定事項を順に読む。直下にはこの入口だけを置き、資料は役割ごとのフォルダへ分ける。

## 読む順

1. [01 要求整理](01-needs/README.md)：背景、利用者、利用場面、対象範囲から、必要な結果を理解する。
2. [02 要件定義](02-definition/README.md)：必要な結果を機能・非機能要件と受入条件へ具体化する。
3. [03 未決定事項](03-open-questions/README.md)：確定していない条件と、確認が必要になる場面を把握する。

[初期MVPの成功条件](../05-decisions/initial-success-criteria.md)は設計判断側に保存した出典資料。現在の要件の入口は [要件一覧](02-definition/requirement-catalog.md) とする。実現方式は [基本設計](../02-architecture/README.md)、未達・未検証の状態は [計画](../../support/02-planning/README.md) で確認する。
