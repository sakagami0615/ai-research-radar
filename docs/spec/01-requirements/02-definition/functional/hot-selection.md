# F-03 根拠付きHOT選抜

UC-01に対応する。大量通知ではなく、AIエンジニアが確認する価値の高い少数の候補を、根拠と採否理由付きで得られること。

## 受入条件

- Agent経路で選抜する候補は、関連性・新規性・重要性・読者への影響・採否理由・未確認事項を記録する。
- 選抜には内容を確認できた一次根拠が必要。URLやHTTP 200だけで確認済みとしない。
- 選抜0件を許容し、保留理由・確認範囲と、未実行や失敗を区別する。
- Agent経路の上限は通常2件、明示指定でも5件。枠を埋めることを目的にしない。
- 品質改善目標として、観測指標の欠損や参考点だけで重要な研究を保存前に落とさない。

現行一括dailyは決定論的な別経路で、内容評価済みであることを保証しない。一括dailyでの自動昇格廃止は [変更設計](../../../05-decisions/audit-remediation/README.md) の目標であり、現行動作との差がある。[現行スコア](../../../03-detailed-design/pipeline/scoring.md)と [選抜入力契約](../../../03-detailed-design/data-models/hot-selection.md)を参照。
